= Hatsu Yakitori

**Hatsu Yakitori** — это экспериментальная библиотека Scheme, которая исследует пересечение *Геометрической декомпозиции*, *Теории кодирования* и *Потока управления*.

Она реализует адаптивный алгоритмический фронтир, который переключается между стратегиями *DFS (Stack)* и *BFS (Queue)* на основе энтропии информационных битов *кода Голея*. Эта логика применяется к декомпозиции графов KAK (Картана) и методам быстрого мультиполя (FMM) на сетках Гоппа. Основные алгоритмы формально верифицированы с помощью **Lean 4** и библиотеки Mathlib.

=== Быстрый старт

  curl -LO https://github.com/Yoshyhyrro/hatsu-yakitori/releases/download/fmm-v0.4.1/hatsu-fmm_0.0.1_amd64.deb
  sudo apt install ./hatsu-fmm_0.0.1_amd64.deb
  hatsu-fmm --check-env
  hatsu-fmm --check

=== Основные команды

  hatsu-fmm --help
  hatsu-fmm --check-env
  hatsu-fmm --list-caps
  hatsu-fmm --check

+--check-env+ проверяет импорт ядра и базовые константы окружения.
+--check+ выполняет лёгкую самопроверку: константы, генерацию сетки, генерацию иерархии и одно синтетическое вычисление FMM.

Пример вывода +--list-caps+:

  INFO[CAPS001]: command-modes=compute,help,check-env,list-caps,dry-run,benchmark,check,explain
  INFO[CAPS002]: runtime=CHICKEN Scheme
  INFO[CAPS008]: c-abi=not-packaged-in-this-slice
  INFO[CAPS009]: input=generated-or-s-expression-file

Пример вывода +--check-env+:

  INFO[ENV001]: fmm-cli-version=0.1.0
  INFO[ENV002]: machine-epsilon=<platform value>
  INFO[ENV003]: kernel-import=ok, sample-grid-size=8
  INFO[ENV004]: default-near-field-cutoff=0.5

Пример вывода +--check+:

  INFO[CHECK001]: machine-epsilon is available and positive
  INFO[CHECK005]: FMM evaluation returned a numeric complex pair
  INFO[CHECK006]: summary passed=5 failed=0

=== Текущие ограничения

* runtime: CHICKEN Scheme
* +--threads+ принимается, но выполнение остаётся однопоточным
* +--theta+ принят для стабильности интерфейса, но вычислитель всё ещё использует встроенный cutoff
* без +--input+ CLI использует синтетическую задачу
* C ABI в этом пакете не публикуется

== Основные концепции

Библиотека построена на трёх теоретических столпах:

=== 1. Адаптивный фронтир Голея

Традиционные алгоритмы обхода графов обычно выбирают конкретную структуру данных (Stack или Queue). Эта библиотека вводит +make-adaptive-frontier+, который динамически выбирает свой режим на основе веса Хэмминга τ целого числа +info-bits+.

Граница перехода — **τ = 12**, соответствующая классу кодового слова додекада. Пять классов весов +{0, 8, 12, 16, 24}+ — единственные ненулевые веса в расширенном двоичном коде Голея:

* +τ = 0+ — Пустое кодовое слово (w0) — Stack — DFS
* +τ = 8+ — Октада (w8) — Stack — DFS
* +τ = 12+ — Додекад (w12) — Queue — BFS
* +τ = 16+ — Дополнение октады (w16) — Queue — BFS
* +τ = 24+ — Полная поддержка (w24) — Queue — BFS

Эта граница формально верифицирована в Lean 4:

  def FrontierMode.ofTau (tau : ℕ) : FrontierMode :=
    if tau < 12 then .stack else .queue

Интуиция: малый вес Хэмминга означает низкую энтропию (разреженная информация), что требует сфокусированной стратегии поиска в глубину. Большой вес Хэмминга означает высокую энтропию (плотная информация), которая выигрывает от послойного поиска в ширину.

Пять классов весов различимы в 11-мерном аффинном пространстве с минимальным попарным разделением 4/3 (отношение собственных значений Хиды при p = 3). Размеры орбит +{1, 759, 2576, 759, 1}+ в сумме дают +2¹² = 4096+ кодовых слов.

=== 2. Декомпозиция KAK (Картана)

Расположена в +core/kak_decomposition.scm+.

Реализует алгоритм уровневой декомпозиции графа с использованием *коэффициентов логарифмического пространства Картана*.

* *Вход:* граф смежности, исходные узлы и граница +B+.
* *Логика:* использует адаптивный фронтир для распространения расстояний. Веса рёбер масштабируются коэффициентами Картана (+a_k+) на каждом этапе декомпозиции.
* *Выход:* таблица хеша кратчайших расстояний, на которые влияет геометрическая "кривизна" уровней декомпозиции.

Коэффициенты Картана на каждом уровне декомпозиции играют роль, аналогичную порядку мультипольного разложения в FMM — оба контролируют качество аппроксимации при заданном геометрическом масштабе.

=== 3. FMM на сетке Гоппа

Расположена в +modules/fmm/fmm_on_goppa_grid.scm+.

Реализация *метода быстрого мультиполя* над геометрической конфигурацией, известной как *сетка Гоппа* (точки, распределённые на единичной окружности комплексной плоскости). Порядок оценки ячеек (ближнее поле vs. дальнее поле) контролируется фронтиром Голея.

==== Построение сетки

Сетка Гоппа размещает N точек равномерно на единичной окружности комплексной плоскости:

  point_k = e^(2πik/N) = cos(2πk/N) + i·sin(2πk/N)

Реализовано как пары +(cons (cos θ) (sin θ))+, где вся комплексная арифметика (+c-add+, +c-sub+, +c-mul+, +c-div+, +c-pow+) реализована через операции с cons-парами. Параметры +q+ и +m+ в +make-goppa-grid+ зарезервированы для будущей параметризации кода Гоппа.
